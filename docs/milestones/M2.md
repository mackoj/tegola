# Milestone 2 · Catalogue, model and storage: report

**Status:** done on 2026-10-31, on `m2-catalogue-model-storage`; merges into `main` with this report.
Scope: `tasks/plan.md` M2 (page 52, P0).

**Exit test (page 52):** loading `video-game.yml` and `video-media.yml` gives the right field lists for all 13

## What works

- **Type schema v1** (T2.1):
  - `TypeManifest` reads every key PLAN §3.3 lists: lookup, signatures, subtypes with their presets, parts, clocks,
    lookup and additions, supersedes, and the rest;
  - an unknown key anywhere is still an error;
  - `schema/type.schema.json` describes the same shape, and `scripts/validate-types.sh` checks every type file against
    it in `linux-core` and in `scripts/ci.sh`.
- **Subtypes replace the medium tables** (T2.2, D-18, D-35):
  - video games: page 48's five platform subtypes, plus `playStatus` (D-20);
  - music: vinyl, CD, cassette and other;
  - vehicles: car and motorbike;
  - `mediaRules`, `mediumRules` and `kindRules` are gone from the files and the schema.
- **The resolver** (T2.3): `Catalogue.resolve(type, subtype:)` is the one function screens and the import read a type
  through. It applies presets (hide, fill and hide, or narrow; D-34), the subtype's additions, a replacement's place
  on the form and the ladder (D-36), the set's slots from the subtype's parts, and the item level.
- **Validation** has page 48's rules:
  - an addition can't redefine a parent field, and a replacement must be of the same kind;
  - a preset must name a parent field, and its value must be one of the field's options;
  - narrowing only removes options;
  - parts need a set signature, and ladder axes must be scales;
  - at most two signatures;
  - clocks and renderers must come from the app's libraries;
  - no type field takes an item-level key;
  - a subtype with more than five additions is flagged for review, not blocked.
- **The item level, the clock library and the signature kit** (T2.4, D-37):
  - `item.yml` has Signed, Bundle of and `bundleSealed`;
  - six named clocks, each with what it reads and its parameters, and `-pending` for a clock held back;
  - six renderers.
- **Domain values** (T2.5):
  - typed UUID ids that the model never makes itself;
  - `FieldKey`/`FieldValue`, one key space for the spine, condition, ladder axes, notes and fields;
  - the shelf's values, `ShelfEvent` (seq, at, source, batch, kind) and `ShelfCommand`.
- **`plan` and `apply`** (T2.6, D-38): pure functions. `plan` checks a command against the rules and turns it into
  events; `apply` is the projection. Replaying the log from an empty shelf rebuilds the same shelf.
- **`TegolaStorage`** (T2.7, D-39):
  - the first migration under `SyncEngine`'s rules;
  - `ShelfStore.perform` appends the events and upserts the changed rows in one transaction, and a refused command
    writes nothing;
  - `rebuildProjection()` and `history(of:)`.
- **`ShelfClient`** in `TegolaClients` (T2.8): its live value is a store with the time from `date` and ids from
  `uuid`, and its test value is unimplemented. Alongside it:
  - `bootstrapDatabase`;
  - the debug-only seed shelf (16 objects across the four v1 types, planted through `perform`);
  - `AppBootstrap`, which the app calls from its `init`, so `--reset` and `--seed` now work.

`linux-core` passed on every push, so the catalogue and the model are proven on Linux (Swift 6.4.2) too. So is
`TegolaStorage`: GRDB needs `libsqlite3-dev`, which CI now installs, and once `uuid()` was registered (review finding
7) its 10 tests passed there. It's a blocking part of `linux-core` and `test-linux.sh` from M2 on.

**The promises as properties** (PLAN §3.4): `PromiseTests` runs 40 seeded sequences of 60 random commands for each
v1 type. After every step it checks:
- promise 1: no value the collector typed is overwritten;
- promise 2: no object is merged or removed;
- promise 3: history only grows;
- promise 6: a count is never lent;
- promise 7: `acquired` is never invented;
- promise 8: nothing is confirmed without the collector.

It also checks that the replay equals the live shelf. To prove the properties can fail, I planted three bugs in `plan`
one at a time: a lookup that overwrites, a capture that confirms itself, and a count that can be lent. Each failed its
property, and each was reverted. Promises 4 and 5 are about counts and screen state, so they arrive with the Shelf
summary in M3.

**The replay test** (`TegolaStorage`): eight seeded sequences of 50 commands per v1 type, on a real SQLite database.
The tables must equal the model's replay of the log, and must be unchanged by `rebuildProjection()`. A planted bug in
the projection writes failed both checks.

## Review

A separate review agent read the branch against the plan, PLAN §3 and D-34 to D-39. It found six bugs, three tests
that didn't test what they claimed, and three disagreements with the spec. Two bugs were confirmed with a throwaway
test, since deleted. The Linux probe confirmed finding 7 on its own: every insert there failed with
`unknown function: uuid()`.

1. **A rebuilt projection drifted on a real clock.** Event times were read back from a millisecond text column, and
   StructuredQueries' JSON coders round dates the same way. Every `data` column, events included, now holds
   Foundation JSON, which is exact. Test: `aRealClockRebuildsExactly`.
2. **The log replayed by `(at, seq)`,** so a clock going back reordered commands. It now replays by `seq`. Test:
   `aClockGoingBackDoesntReorderTheLog`.
3. **A wanted object could be graded** through `.field("mediaCondition")`. Scales are now set only through `.axis`.
4. **A lookup could write `acquired`, money or a grade, or empty the title.** It can't now, and the generator offers
   `acquired` to lookups, so promise 7's property covers it.
5. **A key the collector cleared was refilled by the next lookup.** Objects keep the keys the collector typed or
   cleared (`typed`). Promise 1's property now checks those keys, and the generator clears keys. Dropping the guard
   fails the property.
6. **An origin wasn't checked against its source,** so a lookup could add a "typed", confirmed object. Now it must
   match (`originMismatch`), and promise 8's property checks the source.
7. **The `uuid()` test passed on the platform's own function.** `ShelfStore.configuration` registers one backed by the
   dependency, and the test asserts the exact id.
8. **Promise 3 was circular.** Triggers now make SQLite refuse an update or delete on `events`. Test:
   `theLogCantBeChangedOrEmptied`.
9. **The property tests never used a subtype.** Half the generated objects now take one.
10. **`markBorrowed` accepted the collector's own object,** dropping it from the counts. It now needs an object added
    as borrowed.
11. **Values aren't checked against their field's kind or options,** and hidden fields can be edited. Deferred to M3
    with the edit form (D-40).
12. **D-36's replacement** reads close to a rename. It's documented and loses nothing; it's the owner's call.

Nits taken: `setOwned` on a wanted object clears its priority and price cap. Nits left:
- `item.yml` isn't checked by the schema script;
- the foreign keys mix cascades with soft deletes;
- `perform` loads the whole projection per command. Fine for v1; an import is one command.

## Decisions

M2 added D-34 to D-40:
- **D-34:** what a subtype's preset means;
- **D-35:** what the medium tables become, and what the move dropped;
- **D-36:** a subtype's replacement field, and sets with no slots;
- **D-37:** the item level, and the clock and signature libraries;
- **D-38:** how `plan` reads the rules it isn't told;
- **D-39:** the first storage migration;
- **D-40:** what `plan` doesn't check yet (values against their field).

**For the owner:** D-35 drops music's per-medium names for the packaging and service fields (Sleeve, Case, J-card),
because a subtype can't rename a parent field (page 48). D-38 treats imported rows as confirmed. Either is a quick
change if you read the spec differently.
